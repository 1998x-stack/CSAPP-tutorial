CHAPTER 11 · STORAGE TECHNOLOGIES

为什么换一种访问顺序，内存就像变快了？

同一份数组、相同的计算量，只是调整遍历顺序，CPU 等待数据的时间就可能相差很大。答案不在算术，而在数据怎样穿过存储层次。

数据去哪儿了局部性存储山SSD 与 FTL动手验证
11.1 · 问题与整体模型

CPU 不是直接从 SSD 里“取一个整数”

现代计算机采用多个层次保存数据：寄存器、处理器缓存（通常用 SRAM）、主存（DRAM）和持久存储（SSD/HDD）。不同层次的容量、功耗、价格与访问代价不能同时最优。处理器希望大部分访问在更近的一层完成，只有找不到数据时才付出向下层搬运的代价。

SRAM 靠多个晶体管构成的存储单元保持状态，通常不需要 DRAM 式定期刷新，但位密度较低；DRAM 依靠电容电荷保存信息，需要刷新，适合较大容量的主存。NAND Flash 不断电也可保留数据，但写入与擦除具有不同粒度；机械硬盘的寻道与旋转则引入额外访问开销。

不要背固定的纳秒表。 L1 命中延迟、DRAM 访问时间、SSD 读延迟会随硬件、访问模式、队列深度和工作负载改变。理解谁在搬运什么比记住“L1 必定 1 ns”更重要。

11.2 · 最关键的程序性质

局部性让小而快的缓存变得有用

时间局部性指近期访问过的位置可能再次被访问；空间局部性指相邻地址常被连续使用。缓存通常按整条 cache line 搬运，而不是只为单个 int 搬运四个字节。因此，读取连续元素往往能用上同一次搬运的其余数据。

// C11：同一份数据，两种次序；N 仅作示意
for (size_t i = 0; i < N; ++i)
    for (size_t j = 0; j < N; ++j)
        sink += a[i][j];      // 相邻列，地址连续

for (size_t j = 0; j < N; ++j)
    for (size_t i = 0; i < N; ++i)
        sink += a[i][j];      // 相邻行，跨越行跨度

这里的 sink、a 与 N 需由完整程序定义；此片段是教学伪代码，不能直接单独编译。真实表现还取决于矩阵规模、编译器优化、预取器、页映射和缓存容量。C11 草案 N1570 中多维数组的规则解释了这种地址连续性。

11.3 · 可观察的结果

Memory Mountain 为什么像一座山？

在 CS:APP 的 Memory Mountain 思路中，横向改变工作集大小，纵向改变访问步长，记录读取吞吐量。工作集从较小缓存扩展到主存时，复用位置和失效率改变；步长变大时，每次搬入的缓存行可能只有一小部分被访问。二维参数共同塑造了吞吐量曲面。

这不是一套在所有 CPU 上都成立的固定数值。硬件预取、并发内存请求、带宽饱和、NUMA、频率变化都会改变曲线；吞吐量与一次随机加载的延迟也不能等同。

11.4 · 持久存储的另一种不对称

SSD 写一次 4 KB，为什么可能写得更多？

许多 NAND 设备以页为编程单元、以更大的块为擦除单元。已经写入的物理页通常不能像 DRAM 那样原地覆盖。FTL（Flash Translation Layer）把主机逻辑块地址映射到物理位置；一次更新可以写入空闲页、使旧页失效，然后在日后垃圾回收时整理有效数据并擦除块。

当垃圾回收需要搬移仍有效的页时，NAND 的物理写入量可能超过主机请求量；准确系数与过量预留空间、写入模式、设备固件和统计口径有关。TRIM/discard允许主机告知设备某些逻辑块不再需要，但并不保证每条通知立即回收或立即提升性能。

在 Linux 上可参考 fstrim(8) 检查文件系统如何把不再使用的块告知底层设备。是否启用周期性 TRIM 或在线 discard 应结合系统支持与业务负载评估。

11.5 · 可复现的小实验

先验证“顺序不同，结果仍应相同”

下面的 C11 程序在固定的 16×16 数组上分别进行按行与按列求和，断言两者结果相同。这检验的是访问次序与语义，不是性能差异；数组过小，不足以展示存储山。

#include <assert.h>
#include <stdio.h>
int main(void) {
    int a[16][16];
    int row = 0, col = 0;
    for (int i = 0; i < 16; ++i)
        for (int j = 0; j < 16; ++j) a[i][j] = i * 16 + j;
    for (int i = 0; i < 16; ++i)
        for (int j = 0; j < 16; ++j) row += a[i][j];
    for (int j = 0; j < 16; ++j)
        for (int i = 0; i < 16; ++i) col += a[i][j];
    assert(row == col && row == 32640);
    printf("row=%d col=%d\n", row, col);
    return 0;
}

若要研究性能，需要扩大工作集、重复测量并避免编译器把整段计算优化掉；应同时报告 CPU、编译选项、输入规模与采样方式。不要把上面的正确性检查误称为基准测试。

带走的模型：存储层次不是“越快越好”的简单排序，而是数据在各级间被移动、保留和再次使用的过程；局部性决定了这些搬运有多值得。
