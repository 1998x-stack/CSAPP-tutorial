Chapter 10 · Optimizing Program Performance

程序为什么慢？
先看依赖链

从 CPE 的可信测量开始，区分编译器能做什么、指针别名阻碍了什么，以及循环展开何时真的缩短关键路径。

两个版本的求和循环可能拥有相同的时间复杂度，却在同一机器上显示不同的执行时间。原因可能是函数调用、访存、数据依赖、分支，也可能只是实验噪声。优化的第一步不是改代码，而是建立可重复的基线。

如何测量优化障碍代码移动多路累加性能下界可运行实验
01 / MEASUREMENT

CPE 是直线的斜率，不是随口报出的常数

CPE（Cycles Per Element，每个处理元素所需周期）适合描述长度为 n 的数组循环。对不同规模测量总周期 T(n)，在输入足够大、运行条件相近且规模处于相同性能区间时，常用近似：

T(n)≈C+n×CPE

C 是固定启动开销；CPE 是这一区间的拟合斜率，可能随工作集、指令与平台改变。

Linux 上可借助 perf stat 观测硬件周期数（取决于系统权限及硬件事件支持）。不要混淆墙钟时间与 CPU cycles，也不要把一次 perf stat 的总周期直接除以 n 就称为普适 CPE。

gcc -O3 -std=c11 -Wall -Wextra sum.c -o sum
# 确保输入规模相同、结果被使用，并在同一机器多次运行
perf stat -r 5 -e cycles,instructions ./sum 10000000
# 若受 perf_event_paranoid 等限制，可改用可靠的计时实验；不伪造数据

进行对照时尽量固定编译器选项、CPU 频率条件和工作负载；预热、重复采样，并检查向量化、缓存行为与数据规模改变后结果是否还成立。

02 / COMPILER

编译器为什么不敢合并这两次内存访问？

编译器可以做常量传播、循环优化与自动向量化，但必须保持 C 程序被标准定义的可观察行为。下面两个函数看起来都在“加两次 *yp”，当指针别名时却根本不等价：

void twiddle1(long *xp, long *yp) {
    *xp += *yp;
    *xp += *yp;
}
void twiddle2(long *xp, long *yp) {
    *xp += 2 * (*yp);
}
/* 若 xp == yp 且初值为 5（无溢出）：
   twiddle1 得到 20，twiddle2 得到 15。 */

不可盲改：restrict 表达程序员对不重叠访问的承诺；只有调用者确实满足它的约束才能添加。把原函数无条件换成第二个，不是性能优化而是语义改变。

函数调用也可能观察或修改全局状态。编译器无法证明调用无副作用时，不能随意把它移出循环。相反，把真正在循环中不变且可安全缓存的数据写得明确，可帮助优化器。

03 / CODE MOTION

把重复寻找长度，改成一次寻找

若字符串内容只做 ASCII 大写到小写的就地转换，且输入是有效的以 NUL 结尾的字符串，这个转换不会改变字符串长度。于是长度检查不必每轮重新扫描：

#include <stddef.h>
#include <string.h>

void ascii_lower(char *s) {
    size_t n = strlen(s);         /* O(n) 一次 */
    for (size_t i = 0; i < n; ++i) {
        if (s[i] >= 'A' && s[i] <= 'Z')
            s[i] = (char)(s[i] - 'A' + 'a');
    }
}

这比每轮在条件中都写 strlen(s) 更清楚地表达了循环不变量。注意：若循环会写入字符串终止符、指针可别名到相关存储，或输入根本没有合法终止符，就不能照搬“先缓存长度”的结论。

“strlen 在循环里一定导致 O(n²)”也不是可靠的实测结论：足够聪明的编译器有时会把它移出，具体行为取决于源码、别名分析、优化选项与库实现。要检查生成的汇编，而不是只凭源代码预测速度。

04 / DEPENDENCIES

循环展开本身不会打断依赖链

假设每次浮点加法都依赖上次产生的累计值。即使把循环展开四次，写成连续四句 acc += a[i]，关键路径仍然串行。改成 4 条独立累加链，处理器才可能同时调度多个加法。

double sum4(const double *a, size_t n) {
    double s0=0, s1=0, s2=0, s3=0;
    size_t i = 0;
    for (; i + 3 < n; i += 4) {
        s0 += a[i];     s1 += a[i+1];
        s2 += a[i+2];   s3 += a[i+3];
    }
    double out = (s0 + s1) + (s2 + s3);
    for (; i < n; ++i) out += a[i];
    return out;
}

浮点语义边界：由于舍入误差、NaN、带符号零等细节，改变加法结合顺序可能改变结果，甚至逐位不一致。需要逐位一致的场景不能直接使用这种重组；允许数值容差也应明确误差目标。

05 / BOTTLENECK

延迟与吞吐上限，会在哪儿相遇？

一个仅用于直觉的模型：假定每个元素做一次同类操作，操作延迟为 L 周期，处理器每周期最多启动 r 次该操作，循环维护 k 条相互独立的累加链，忽略访存、分支与乱序窗口限制。则单元素平均周期的理论下界：

CPE≥max(Lk,1r)

仅对该简化独立链模型成立；实际瓶颈可能是加载带宽、缓存未命中、前端或编译器优化。

06 / REPRODUCE

一个可编译的微基准：先确保结果没被优化掉

复制下面完整的 C11 示例到 sum.c。串行和四路函数在同一输入上计算，并打印结果，避免“看似跑了循环、实际被编译器删除”的最常见陷阱。它只负责功能对照，正式性能比较仍需多次采样及检查汇编。

#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>

static double sum1(const double *a, size_t n) {
    double s = 0;
    for (size_t i = 0; i < n; ++i) s += a[i];
    return s;
}
static double sum4(const double *a, size_t n) {
    double s0=0, s1=0, s2=0, s3=0;
    size_t i = 0;
    for (; i + 3 < n; i += 4) {
        s0 += a[i]; s1 += a[i+1];
        s2 += a[i+2]; s3 += a[i+3];
    }
    double out = (s0+s1)+(s2+s3);
    for (; i < n; ++i) out += a[i];
    return out;
}
int main(int argc, char **argv) {
    if (argc != 2) return 2;
    char *end = NULL;
    unsigned long long requested = strtoull(argv[1], &end, 10);
    if (end == argv[1] || *end || !requested ||
        requested > SIZE_MAX / sizeof(double)) return 2;
    size_t n = (size_t)requested;
    double *a = malloc(n * sizeof(*a));
    if (!a) return 1;
    for (size_t i = 0; i < n; ++i)
        a[i] = (double)(i % 37) / 37.0;
    printf("sum1=%.17g sum4=%.17g\n", sum1(a,n), sum4(a,n));
    free(a);
    return 0;
}

执行：gcc -O3 -std=c11 -Wall -Wextra sum.c -o sum && ./sum 1000000。若使用 -ffast-math 或 -Ofast，浮点语义和优化空间会发生变化，不能与严格编译条件下的结果混为一谈。
