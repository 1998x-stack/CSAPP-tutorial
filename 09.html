Chapter 09 · Pipelining

让五条指令
同时向前走

流水线不让一条指令的工作消失，而是让多个指令的不同步骤重叠。理解它，要同时看清时间、依赖与恢复。

第 8 章的 SEQ 在一个较长的周期中完成一条指令。若把这条长组合路径分成五段，中间放入流水线寄存器，我们就能让第二条指令在第一条离开取指后立刻开始。吞吐率与延迟是不同的问题。

时间轴性能模型数据依赖分支恢复精确状态动手推演
01 / TIME

为什么五个工位能接连完成任务？

CS:APP 的 Y86-64 PIPE 分成五个阶段：取指 F、译码 D、执行 E、访存 M、写回 W。同名的 F/D/E/M/W 流水线寄存器保存对应阶段所需的状态；这里没有独立的第六个“PC 更新流水级”。

注意第一条指令直到第 5 个周期才能结束，而第 2、3、4 条指令已经在运行。稳态吞吐率可接近每周期一条，单条指令仍需通过五级。 若阶段不平衡，最慢阶段和流水线寄存器开销决定周期长度。

02 / MODEL

写下模型，再谈“加速几倍”

假设五个阶段分别耗时 t₁…t₅，每个流水级额外付出开销 δ。没有停顿、分支失败或内存等待时，处理 n 条指令：

TSEQ≈n×∑i=15ti TPIPE≈(n+4)×(maxiti+δ)

五级流水线的填充与排空成本为 4 个周期；此式忽略冒险与其他开销。

例如每级 200 ps、寄存器额外开销 20 ps、共 8 条指令：SEQ 约 8 × 1000 = 8000 ps，PIPE 约 (8 + 4) × 220 = 2640 ps，理论加速约 3.03×，不是直接声称“5×”。真实值要看冒险、缓存与时钟频率。

交互 · 改变指令条数，观察填充开销

该模型固定五个各 200 ps 的阶段与 20 ps 寄存器开销；不模拟依赖、缓存和分支。

03 / DEPENDENCY

下一条要读的值，上一条还没交出来

考虑两条相邻指令。若前者写 %rax、后者马上读 %rax，这叫 RAW（Read After Write）数据依赖。经典有序 PIPE 可将较早指令刚算出的值转发到 Decode 的输入选择逻辑，无需等到常规寄存器写回。来源包括 Execute 结果、Memory 结果及 Write Back 所携带的值；越新的匹配结果优先。

addq   %rbx, %rax       # ALU 产生新的 %rax
subq   %rax, %rcx       # 紧随其后，可以使用转发结果

mrmovq 0(%rbx), %rax    # 必须到 M 阶段才得到内存数据
addq   %rax, %rcx       # 紧随其后的 load-use：需 1 个气泡

RAW 是必需处理的真实依赖。WAR 与 WAW 在经典固定阶段、按序完成的五级模型中不会表现为同样的硬件冒险；乱序执行处理器则需要考虑寄存器重命名和提交顺序。

交互 · 这两条指令需要停顿吗？

无需停顿

两条指令没有 RAW 依赖，正常进入下一流水级。

04 / CONTROL

走错分支可以回头，但不能留下痕迹

条件跳转在 Execute 才确定方向；Fetch 却早已取到后续指令。教学版 PIPE 对条件跳转预测跳转（taken），错误时把错误路径上的年轻指令变为气泡，从正确 PC 重新取指。目标可以从指令字节中得到；不能凭空断言教学 PIPE 一定具有 BTB。

ret 需要等返回地址从栈内存读出。简化 PIPE 的取指会在 ret 处于 D/E/M 时等待，直到返回地址可用于选择正确 PC。这不是让机器永远停住，而是用有限停顿换取正确控制流。

安全边界：Spectre 说明，错误路径上的瞬态执行可能通过缓存等微架构状态泄漏信息；Meltdown 涉及不同的瞬态执行与权限检查问题。二者不能简单等同，也不能从教学版 Y86-64 模型直接推出某款真实 CPU 的漏洞。

05 / CORRECTNESS

错误出现时，哪些状态可以真的写下去？

HLT、非法指令（INS）、无效地址（ADR）等状态需要随着指令经过流水线。对于精确的程序状态，更年轻的指令不能在更老的异常指令之后留下架构可见副作用。教材 PIPE 通过控制访存、写回与条件码更新，直到异常状态到达 W 才停止处理器。

这里的 Y86-64 教学模拟器不是完整的操作系统：Stat 变为异常状态不等于“自动保存上下文并切换到内核异常处理程序”。讨论真实 CPU 时还需考虑更复杂的提交机制。

06 / EXERCISE

用纸笔或代码重画时空图

先对四条完全独立的指令列出每级的开始周期；再将第 2 条替换为紧邻的 load-use 消费者，问：哪个周期 F/D 需要停顿？E 何时插入气泡？下面的 Python 仅验证理想五级流水线的起始时序，不是周期精确的完整 Y86 模拟器。

stages = "FDEMW"
schedule = {(inst, stages[stage]): inst + stage + 1
            for inst in range(4) for stage in range(5)}
assert schedule[(0, "F")] == 1
assert schedule[(0, "W")] == 5
assert schedule[(3, "W")] == 8
assert len(set(schedule[(i, "W")] for i in range(4))) == 4
print(schedule[(3, "W")])  # 8
