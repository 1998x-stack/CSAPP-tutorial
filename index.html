Computer Systems · A Learning Journey

从一行 hello，走进计算机系统的内部。

程序为什么能运行？一次内存访问究竟发生了什么？服务器又如何处理许多同时到来的请求？沿着这些问题，循序理解数据、指令、硬件与操作系统之间的连接。

Follow the system

一段程序的四次追问

  1. 它表示什么？bits / float

    数据如何编码，为什么相同的位会有不同解释？

  2. 它如何执行？mov / call

    指令、寄存器与栈如何把源码变成动作？

  3. 它存在哪里？cache / VM

    缓存、地址翻译和进程如何管理有限的资源？

  4. 它如何连接世界？I/O / threads

    文件、网络和并发如何让程序成为服务？

从问题出发，逐层揭开机制，再用代码验证直觉。

03 · Follow a real system

不只是按章节读：跟踪一个问题穿越系统。

同一个现象常常横跨源代码、机器指令、硬件与操作系统。下面三条链路提供可解释的跨章节入口；每一步都可以独立打开。

TRACE 01 · EXECUTION

从一行 Hello 到进程启动

源码如何得到可执行文件，又如何成为内存中运行的进程？

  1. 01源程序经过编译
  2. 13链接器解析符号

最终能解释：为什么“编译成功”和“运行成功”不是同一件事。

TRACE 02 · MEMORY

一条访存指令为何要等待

有效地址是怎么形成的？Cache、TLB 和地址翻译分别做什么？

  1. 04指令计算有效地址
  2. 11存储层次与局部性
  3. 12Cache 组、行、缺失
  4. 17虚拟地址与页表翻译

最终能解释：缓存未命中与 TLB 未命中不是一回事。

TRACE 03 · SERVER

一次 HTTP 请求如何安全完成

读到几个字节并不等于读完一条请求；并发又引入了生命周期问题。

  1. 19短读短写与文件描述符

  3. 23队列、线程池和同步

最终能解释：为什么高并发首先要保证报文完整性和所有权。
