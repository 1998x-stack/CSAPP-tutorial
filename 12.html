CHAPTER 12 · CACHE MAPPING

为什么缓存还有空位，却偏偏装不下两个数？

两个地址只相差 64 字节，在一个极小的直接映射缓存里也可能反复驱逐彼此。原因不是总容量用完，而是地址中的几位决定了它们必须去同一个组。

地址拆分动态追踪3C Miss矩阵分块实验
12.1 · 从一条缓存行开始

容量不是一袋任意摆放的字节

经典教学模型的缓存由 S 组（sets）、每组 E 行（ways）及每行 B 字节（block/line）组成。数据容量 C = S × E × B；每行另有有效位、标签和实现相关的替换状态等元数据，C 不包含这些开销。若有 4 组、每组 2 行、每行 16 B，则数据容量为 128 B。

C=S×E×B=4×2×16=128 B
教学模型只计算数据存储容量

在 S 和 B 都是 2 的幂、按简单模映射的模型中：低 b=log₂B 位给出块内偏移，随后 s=log₂S 位选组，余下高位作为标签。组内只要有一行有效且标签匹配，就是命中；否则发生未命中并进行填充/替换。

// 假设本题地址宽度为 16 位
unsigned addr = 0x1234;
unsigned offset = addr & 0xf;       // 4
unsigned set = (addr >> 4) & 0x3;  // 3
unsigned tag = addr >> 6;         // 0x48

直接映射是 E=1；多路组相联是 E>1；全相联则是 S=1、E=C/B，并不是“E 等于 S”。真实处理器还可能采用复杂索引、不同缓存层级及地址翻译相关设计，先掌握这个清晰的抽象模型。

12.2 · 让一个冲突发生在眼前

0x00 与 0x40，为什么相遇在 set 0？

仍取 S=4, B=16：地址 0x00 的块号是 0，0x40 的块号是 4；两者 block mod S 都为 0，但标签分别为 0 和 1。对于直接映射，它们必然轮流占据唯一一行；对于 2 路组相联，它们可以同时留在组 0 的两行。

空组：两路都无有效数据

按顺序点选步骤，观察标签与命中结果。

对照直接映射（E=1），访问序列 0x00 → 0x40 → 0x00 会得到未命中、未命中、未命中；2 路缓存则是未命中、未命中、命中。这里讨论读访问与填充，尚不涉及写回、替换策略或多级缓存。

12.3 · 三个不同的“慢”

3C Miss：区分第一次、装不下与放错位置

冷不命中

某个块此前从未被带入该缓存。第一次触及该块时通常发生，依访问历史与预取等条件而定。

容量不命中

在给定容量下，即使采用理想化的全相联缓存，复用距离仍可能太大而被逐出。

冲突不命中

相同总容量下，组索引/关联度让本可共存的块互相竞争位置。

“3C”是在指定缓存模型与替换策略下帮助解释失效的分类，而不是 perf 计数器自动输出的三个独立数值。特别是现代处理器中的预取、替换启发式、共享缓存等因素会让实测现象更复杂。

常见误解：有 32 KB 的数组并不意味着它“恰好适合 32 KB 的 L1”；同时活跃的栈、代码、其他数据以及组冲突都会争用容量。不能从“数组大小小于 L1”直接推断零未命中。

12.4 · 从地址位走回代码

矩阵乘法中，改变循环次序会改变数据流

对于 C 的行优先布局，朴素 i-j-k 乘法在内层按列读 B[k][j]，可能不断跨行；改成 i-k-j 后，在内层顺序读取 B[k][j] 和更新 C[i][j]。但 i-k-j 版本必须先把 C 清零，因为它执行的是累加，而非直接赋值。

// C11；N 为编译时常量，A/B/C 为 N×N double 数组
for (int i = 0; i < N; ++i)
    for (int j = 0; j < N; ++j) {
        double sum = 0;
        for (int k = 0; k < N; ++k)
            sum += A[i][k] * B[k][j];
        C[i][j] = sum;           // i-j-k
    }

// 下面是另一种算法，执行前须初始化 C 为零
for (int i = 0; i < N; ++i)
    for (int k = 0; k < N; ++k)
        for (int j = 0; j < N; ++j)
            C[i][j] += A[i][k] * B[k][j];  // i-k-j

以上是与外层变量定义配合的教学片段，并不单独构成可执行程序。更大矩阵还可分块（tiling/blocking）：让活跃的 A/B/C 子块尽可能重复使用；块尺寸需要结合缓存层次和实际测量决定，不能断言“64×64 三个 float 子块一定都能装进某款 L1”。

改变循环次序对浮点求和的舍入顺序可能有影响；并行化、向量化、编译器重排和 BLAS 内核还可能比手工简单分块更有效。优化前先保证数值正确性，之后再测量吞吐率、延迟与缓存行为。

12.5 · 可执行而不是猜测

两个小实验：验证映射，验证分块

实验 A（cache_mapping.c）将访问序列喂给极小的直接映射与两路缓存模拟器；它断言前者三个 miss、后者两次 miss 后一次 hit。模拟器仅实现本例需要的读填充与简化替换，不代表真实 CPU。

cc -std=c11 -Wall -Wextra -Werror labs/cache/cache_mapping.c -o /tmp/cache_mapping
/tmp/cache_mapping
# 应输出：direct=MMM two-way=MMH

实验 B（matmul_block.c）采用 N=7、TILE=3，包含尾块不满的情况。两个算法对小的整数值进行 double 运算，并比较结果；同样是正确性测试，未生成或冒充任何性能数据。

cc -std=c11 -Wall -Wextra -Werror labs/cache/matmul_block.c -o /tmp/matmul_block
/tmp/matmul_block
# 应输出：naive and tiled results match

要做可信的性能比较，应针对多个矩阵规模、不同块大小、重复运行与稳定频率环境测量，并报告 CPU 型号、编译器、优化选项、数据对齐和采样方式。perf 的原始计数器也不总能直接区分前述 3C 原因。

带走的模型：先按块号选择 set，再比较 tag，最后靠 offset 找到数据；组织结构限制了“可能保留什么”，而访问次序决定“是否真的复用它”。
